# MENADevs Project Samples

This repository is a curated collection of sample projects and technical tasks showcasing MENADevs’ capabilities across software engineering, evaluation environments, data processing, security analysis, and complex implementation work. It has been prepared for direct client review as a practical representation of the breadth and quality of our work.

## Sample Projects

### Evaluation and Benchmark Tasks

| Project | Description |
| --- | --- |
| [Electronic Store Evaluation Environment](projects/electronic-store-evaluation-environment/) | Electronic-store evaluation materials featuring a Python entry sample, data-model documentation, workflow diagrams, and supporting artifacts. |
| [TBench Sample 2](projects/tbench-sample-2/) | A Dockerized Node.js benchmark focused on deterministic email-suppression decisions, supported by Python validation tests. |
| [Ultra Long Horizon Sample Work](projects/ultra-long-horizon-sample-work/) | A long-horizon Rust implementation task covering the SQL layer of a distributed database, with evaluation tooling and recorded runs. |
| [Election Results Reconciler](projects/election-results-reconciler/) | A SkillBench task for auditing and reconciling election records, with a secondary university-program shortlisting task included in the same evaluation package. |
| [Mars Transfer Planner Skill](projects/mars-transfer-planner-skill/) | A mission-planning task combining orbital calculations, PostgreSQL-backed data, Python skills, and reproducible Docker tooling. |
| [Network Threat Forensics](projects/network-threat-forensics/) | A network-forensics investigation covering DNS tunneling, command-and-control beaconing, lateral movement, and data exfiltration. |
| [Grafana Loki 21237](projects/grafana-loki-21237/) | A Phoenix BPO engineering task based on Grafana Loki pull request #21237, preserving the supplied Loki source tree and task context. |

## Repository Notes

Each project is self-contained within the [`projects/`](projects/) directory. Supplied source code, datasets, evaluation materials, and supporting artifacts are preserved as received, while repository-level documentation provides a consistent structure for review.

See [`NAMING.md`](NAMING.md) for the mapping between original source names and their normalized repository folders.
