# تدقيق التبعيات وسلسلة توريد البرمجيات

تُعنى هذه المهارة بالمخاطر المرتبطة **بالمكتبات البرمجية ومخرجات البناء**. وهي لا تحل محل مراجعة كيفية تعامل التطبيق مع مدخلات المستخدم أو الجلسات أو عمليات إعادة التوجيه أو ترويسات الاستجابة في شيفرته الخاصة.

## متى تُستخدم هذه المهارة

- عندما تطلب المهمة صراحةً فرز ثغرات `CVE`  أو  `pip audit` أو `npm audit`، أو تصدير  (SBOM).
- عندما يكون الهدف تعزيز أمان عمليات CI/CD أو صور الحاويات الأساسية، وليس إصلاح الدوال المسؤولة عن معالجة المسارات.
- عندما تكون مخاطر الإنتاج الأمنية  ناتجة بشكل أساسي عن حزم قديمة تحتوي على ثغرات معروفة قابلة للاستغلال.


## متى ينبغي خفض أولويتها

- عندما تكون المراجعة فحصًا لأمان تطبيق ويب **على مستوى التطبيق**، مثل ثغرات XSS وملفات تعريف الارتباط وسياسة CSP وعمليات إعادة التوجيه.

- عندما لا يوجد متطلب لتغيير إصدارات التبعيات أو توثيق ثغرات CVE.
- عندما لا يمكن التحقق من النتائج دون تشغيل مصادر خارجية لبيانات الثغرات الأمنية.

في هذه الحالات، استخدم مهارات code-review ومهارات مخاطر أمان الويب وفق OWASP أولًا.


## سير العمل المعتاد (ضمن نطاق سلسلة التوريد)

1. حدّد مدير الحزم وملف تثبيت الإصدارات.
2. شغّل أمر التدقيق الذي يدعمه المشروع على إصدارات الحزم المثبّتة.
3. صنّف النتائج حسب قابليتها للاستغلال في **بيئة النشر هذه تحديدًا** (تبعيات التطوير فقط مقابل التبعيات المستخدمة أثناء التشغيل).
4. وثّق المخاطر المقبولة أو ترقيات الحزم أو الضوابط الأمنية التعويضية.

## المخرجات المتوقعة

يجب أن تتضمن التقارير اسم الحزمة وإصدارها ومعرّف التنبيه الأمني ومستوى الخطورة وطريقة المعالجة (الترقية أو تطبيق تصحيح أمني أو قبول استثناء مع توضيح مبرراته).

## خطأ شائع

استهلاك الوقت والموارد المخصصة للتدقيق في فحص ثغرات CVE المتعلقة بالتبعيات، مع ترك ثغرات الحقن المنعكسة أو المخزّنة وإعادة التوجيه المفتوحة دون إصلاح في شيفرة التطبيق.
