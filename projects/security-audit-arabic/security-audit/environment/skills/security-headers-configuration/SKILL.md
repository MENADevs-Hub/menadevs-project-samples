# إعداد ترويسات الحماية

توجّه ترويسات أمان HTTP المتصفح إلى فرض قيود إضافية. وهي وسيلة دفاع إضافية متعددة الطبقات؛ فلا تحل محل إصلاح الشيفرة التي تحتوي على ثغرات، لكنها تقلل من تأثير المشكلات التي قد تمر دون اكتشافها.


## الترويسات التي يجب مراجعتها

| الترويسة | ماذا تفعل |
|--------|----------------|
| Content-Security-Policy | تقييد البرامج النصية والأنماط والموارد الأخرى المسموح بتحميلها  |
| X-Frame-Options | للحد من  اختطاف النقرات من خلال التحكم في تضمين الصفحة داخل iframe |
| X-Content-Type-Options | الحد من استنتاج نوع محتوى MIME تلقائيًا (`nosniff`) |
| Strict-Transport-Security | تشجيع استخدام HTTPS في الزيارات المستقبلية |
| Referrer-Policy | تقييد بيانات الصفحة المُحيلة التي تُرسل إلى المواقع الأخرى |
| Permissions-Policy | تعطيل ميزات المتصفح التي لا يحتاج إليها التطبيق |

## أسئلة مراجعة  CSP

عند قراءة سياسة موجودة، اسأل:

- هل تُستخدم أحرف البدل (`*`) في أي توجيه؟
- هل يتضمن `script-src` القيمة `unsafe-inline` أو `unsafe-eval`؟
- هل تبدو السياسة صارمة بسبب `default-src 'self'` بينما لا يزال `script-src` متساهلًا؟
- هل يسمح `style-src` أو أي توجيه آخر بصلاحيات أوسع من اللازم؟

أعطِ الأولوية لتشديد التوجيهات وإزالة الكلمات المفتاحية غير الآمنة بدلًا من إضافة استثناءات جديدة.

## نمط التنفيذ في Flask

في Flask، اضبط جميع ترويسات الأمان من خلال  `@app.after_request` مركزية:

```python
@app.after_request
def add_security_headers(response):
    response.headers["Content-Security-Policy"] = "default-src 'self'; script-src 'self'; style-src 'self'"
    response.headers["X-Frame-Options"] = "DENY"
    response.headers["X-Content-Type-Options"] = "nosniff"
    response.headers["Referrer-Policy"] = "strict-origin-when-cross-origin"
    return response
```

لتعزيز أمان ملفات تعريف الارتباط الخاصة بالجلسات، استخدم `app.config`:

```python
app.config["SESSION_COOKIE_HTTPONLY"] = True
app.config["SESSION_COOKIE_SAMESITE"] = "Lax"
```



## الثغرات الشائعة

- ضبط بعض ترويسات الأمان فقط، مما قد يعطي انطباعًا بأن أمان التطبيق قد تم تعزيزه بالفعل
- وجود سياسة CSP مع استمرار السماح بتنفيذ البرامج النصية المضمّنة
- غياب وسائل الحماية من اختطاف النقرات أو ضوابط بيانات الصفحة المُحيلة، حتى بعد تحديث سياسة CSP
- غياب خصائص HttpOnly أو SameSite من ملفات تعريف الارتباط الخاصة بالجلسات

## بعد إجراء التغييرات

أعد اختبار مسارات الاستخدام الأساسية في التطبيق. فقد تؤدي سياسة CSP الأكثر صرامة إلى تعطّل الصفحات التي كانت تعتمد على البرامج النصية المضمّنة أو الموارد التابعة لجهات خارجية.
